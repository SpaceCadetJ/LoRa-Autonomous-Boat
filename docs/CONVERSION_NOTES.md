# Allegro → KiCad Conversion Notes

## Source Files

The conversion was performed from the Specctra DSN export (`senior design v2.dsn`) generated by Allegro PCB Editor 22.1 (build 4063652). The DSN is an S-expression text format containing complete board structure, component placement, footprint library, and netlist data.

**Original project:** `SeniorDesign_Board.opj` (OrCAD Capture) + `senior design v5DRL.brd` (Allegro PCB Editor)

## Conversion Pipeline

A Python script (`generate_kicad.py`) parses the DSN and generates KiCad 9 format files:

1. **Component extraction** — 45 placed components with XY coordinates (mils), rotation, side, value, and footprint assignment
2. **Net extraction** — 35 named nets with full pin-level connectivity
3. **Coordinate transformation** — Allegro uses mils with Y-up origin; KiCad uses mm with Y-down origin. Transform: `kicad_x = offset + allegro_x * 0.0254`, `kicad_y = offset - allegro_y * 0.0254`
4. **Footprint mapping** — Each Allegro footprint name mapped to the closest KiCad standard library footprint
5. **Symbol mapping** — Components mapped to `Device:C`, `Device:R`, `Device:L`, `MCU_ST:STM32F446RETx`, etc.
6. **Custom symbol library** — R1240N001x (buck converter) and TCAN1042H-Q1 (CAN transceiver) created as project-local symbols

## Known Issues and Manual Work Required

### Schematic
- Components are placed in functional blocks but **not wired**. Use `docs/NETLIST.md` as the authoritative wiring reference.
- The schematic is flat (single sheet). Consider reorganizing into hierarchical sheets matching the original OrCAD block structure: Power Supply, MCU, CAN Bus, LoRa, GPS, Outputs, Debug.
- Power symbols (GND, +3V3, VBAT) need to be added as proper KiCad power flags.
- Some symbol assignments may need adjustment — the R1240N and TCAN1042H custom symbols have correct pinouts but should be verified against datasheets.

### PCB
- **Traces are not routed.** The generated PCB only has component placement — all copper routing must be done manually in KiCad's interactive router.
- The board outline is a simple rectangle from the DSN boundary. The actual board outline from the final Allegro revision (`v5DRL`) may differ.
- Copper zones (ground pour) need to be recreated.
- Design rules (clearance 12 mil / 0.3048 mm, trace width 12 mil / 0.3048 mm, via 35 mil pad / 25 mil drill) should be set in Board Setup.
- Silkscreen text and reference designator positions need cleanup.

### Firmware vs. Schematic Discrepancy
The motor/rudder PWM pin assignments appear swapped between the schematic netlist and the firmware `.ioc` file. The firmware uses TIM3_CH1/PC6 for motor and TIM1_CH1/PA8 for rudder, but the schematic net `N04355` (motor) connects to U3 pin 41 (PA8) and `N04395` (rudder) connects to U3 pin 37 (PC6). This should be verified against the physical board.

## DSN File Format Reference

The Specctra DSN format used here follows this structure:
```
(PCB <board_file>
  (parser ...)
  (resolution MIL 1000)
  (structure (boundary ...) (layer ...) (rule ...) (via ...))
  (placement (component <footprint> (place <ref> <x> <y> <side> <rotation> (property ...))))
  (library (image <footprint> (pin <padstack> <number> <x> <y> ...)))
  (network (net <name> (pins <ref-pin> ...)))
  (wiring (wire ...))
)
```

The DSN was exported from Allegro PCB Editor, not from the OrCAD Capture schematic side. This means it contains PCB-level data (placement, footprints, routing) but not schematic-level data (hierarchical sheet structure, symbol graphics, wire routing).
